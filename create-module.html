Create your first FSCSS module

A module is an importable .fscss library: tokens on a root mixin, namespaced @define blocks, package.json metadata so the IDE can libck / enable it, and optional xfcmd scripts that drop demos and snippets. Not a replacement for the project tutorial.

00 · Concept

What counts as a module

An FSCSS module is source you import, not a runtime JS package. After compile (CLI, IDE export, or browser runtime), the consumer ships plain CSS.

  • Solves one job: icons, charts, forms, page shell, overlap UI…
  • Exposes mixins via @define with a clear prefix (@icon-*, @st-*, @progress-*)
  • Puts shared values on a *-root so themes override without editing the module
  • Documents selective import so unused mixins never bloat the CSS
  • Optional: package.json + xfcmds/ so libck my-widget works in the IDE
01 · Anatomy

Recommended file layout

my-widget.fscss/
├── my-widget.fscss      ← all @define exports
├── package.json             ← name, file.*, xfcmd, fscss_version
├── README.md
├── xfcmds/
│   ├── enable.xfcmd         ← libon / yes after libck
│   └── disable.xfcmd        ← liboff (snippets off; keep files)
└── samples/
    └── demo.html

Small packs can ship a single .fscss file. Add package.json and xfcmds/ when you want IDE discovery and one-prompt setup.

02 · Root tokens

One place for theme knobs

my-widget.fscss
@define widget-root(root:root){`
:@use(root) {
  --widget-bg: #12131a;
  --widget-accent: #8f6bff;
  --widget-radius: 12px;
  --widget-pad: 16px;
}
`}
  • Prefix variables (--widget-*) so packs share a page
  • Defaults look good alone; pages override on :root after @widget-root()
  • Optional root param to attach tokens to .theme-dark instead of global :root
03 · @define

Namespaced, parameterized mixins

@define widget-card(sel:.widget-card){`
@use(sel) {
  background: var(--widget-bg);
  border-radius: var(--widget-radius);
  padding: var(--widget-pad);
  border: 1px solid color-mix(in srgb, var(--widget-accent) 25%, transparent);
}
`}

@define widget-accent(color){
  --widget-accent: @use(color);
}
  • Prefix every public name — widget-card, not generic card
  • Selector parameter — sel:.widget-card so callers can retarget
  • One responsibility per mixin — easier selective imports
  • Prefer tokens over hard-coded colors inside shapes

@import ((widget-card as card) from …) renames only in that file. After as, the original name is undefined there (1.2.6 ownership rules).

04 · Consumer API

How others pull your module

/* selective — preferred in production */
@import((widget-root, widget-card) from my-widget)

@widget-root()
@widget-card(.pricing-card)

/* wildcard while exploring */
@import((*) from my-widget)

Registry-style names (no quotes) when listed in the ecosystem; paths and CDN URLs need quotes. Document both forms and the smallest HTML that proves the mixin.

05 · package.json

Metadata the IDE and tooling read

Without file.modules / remote, libck cannot download your source. Helper signatures drive snippets when enable runs.

package.json
{
  "name": "my-widget",
  "version": "1.0.0",
  "description": "Short pure-CSS widget pack for FSCSS",
  "extension": "fscss",
  "fscss_version": ">=1.2.4",
  "engines": { "fscss": ">=1.2.4" },
  "repository": {
    "type": "git",
    "url": "https://github.com/you/my-widget.fscss"
  },
  "bugs": {
    "url": "https://github.com/you/my-widget.fscss/issues"
  },
  "file": {
    "usage": {
      "directive": "widget-*",
      "helpers": [
        "widget-root(root:root)",
        "widget-card(sel:.widget-card)",
        "widget-accent(color)"
      ]
    },
    "modules": ["./my-widget.fscss"],
    "remote": "./my-widget.fscss"
  },
  "xfcmd": {
    "enable": "./xfcmds/enable.xfcmd",
    "disable": "./xfcmds/disable.xfcmd"
  },
  "author": { "name": "you" },
  "keywords": ["fscss", "css", "module"],
  "license": "MIT"
}

Field reference

FieldRole
nameIDE key: libck my-widget. Keep simple (not only the import alias).
extensionShould be "fscss".
fscss_versionRange vs IDE/compiler (>=, ^, \~). Warn if unsatisfied.
file.modulesPaths to module sources (required for download check).
file.remotePrimary remote file path (often same as main module).
file.usage.helpersPublic @define names; add (args) for better snippets.
file.usage.directivePrefix pattern e.g. widget-*. Use "" if names are mixed (avoids false warnings).
xfcmd.enable / disablePaths to .xfcmd scripts for libon / liboff.
blocked_methodsOptional list of FSCSS methods the pack must not use.

Helpers listed in JSON should exist as @define in the module source — libck verifies that. Mismatched names become warnings.

06 · xfcmd

IDE automation: enable, demos, snippets

xfcmds are plain-language scripts (not JavaScript). On enable they can add snippets, create a demo folder, compile, and open preview.

Consumer flow

IDE terminal
libck my-widget
yes
# or
libon my-widget
liboff my-widget

enable.xfcmd (minimal)

# xfcmds/enable.xfcmd
say "Setting up {name}@{version} by {author}"
say "Import: @import((*) from {import})"
add snippets for helpers
create file "my-widget-demo/demo.fscss" with:
  @import((*) from {import})
  @widget-root()
  @widget-card(.widget-card)
  body {
    margin: 0;
    min-height: 100vh;
    display: grid;
    place-items: center;
    background: #0b0c10;
  }
end
create file "my-widget-demo/index.html" with:
  <!DOCTYPE html>
  <html lang="en">
  <head>
    <meta charset="utf-8">
    <title>my-widget demo</title>
    <link type="fscss" href="demo.fscss">
  </head>
  <body>
    <div class="widget-card">Hello module</div>
  </body>
  </html>
end
open file my-widget-demo/demo.fscss
compile
open file my-widget-demo/index.html
show preview
say "Done. Type a helper name in the editor for its snippet."

disable.xfcmd

# xfcmds/disable.xfcmd
say "Disabled {name}. Helper snippets were removed."
say "Demo folder was kept. Delete it if you do not need it."

Useful sentences

  • add snippets for helpers — one snippet per entry in file.usage.helpers
  • create file … with: … end — never overwrites existing files
  • open file → compile → show preview — order matters
  • Variables: {name}, {version}, {author}, {import}, {helpers}, {file}

Full language: xfcmds guide · org scripts: FSCSS/xfcmds. Reference enables: st-core, micros, overlapui, circle-progress.

When the module generates CSS

08 · Test

Prove it before publish

  1. IDE: libck https://github.com/you/my-widget.fscss → fix fails → yes
  2. Runtime: fscss@1.2.6/runtime.min.js + sample
  3. CLI: fscss my-widget.fscss /tmp/out.css — no leftover FSCSS syntax
  4. Override tokens on :root; UI should follow
  5. Selective import of one mixin; others absent from output

Ship CSS

09 · Publish checklist

Before you call it done

  • □ Prefixed public mixins and CSS variables
  • □ *-root (or documented equivalent) for tokens
  • □ Selective @import ((a, b) from …) in README
  • □ fscss_version / minimum version stated
  • □ file.modules + remote + accurate helpers
  • □ directive matches prefix — or "" if mixed names
  • □ Optional xfcmds/enable.xfcmd + disable.xfcmd
  • □ Sample HTML (and optional compiled CSS)
  • □ No unscoped tag styles that break host pages
  • □ Clear license (MIT recommended)
