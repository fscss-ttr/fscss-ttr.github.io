Authoring guide

Create your first FSCSS module

A module is a small, namespaced library of @define helpers plus design tokens. Consumers import only what they need. This guide walks from a single file to a publishable package — the same pattern behind circle-progress, form, and st-core.

00 · Idea

What a module is (and isn’t)

An FSCSS module is not a JavaScript package with a runtime API. It’s a .fscss file (or a few) that exposes parameterized mixins via @define. When someone writes:

@import((badge-root, badge) from my-badge)
@badge-root()
@badge(.status-badge)

…the compiler (CLI or browser runtime) pulls those defines into their stylesheet and expands the calls into plain CSS.

  • Is: tokens + shapes + helpers, pure CSS output
  • Isn’t: a component framework, a JS plugin, or a global style dump
01 · Structure

Anatomy of a small module

my-badge/
├── my-badge.fscss     ← defines + tokens
├── package.json         ← name, helpers list, fscss_version
├── README.md
└── samples/
    └── example.html     ← runtime demo

One source file is enough. Split only when the surface area grows (e.g. themes vs geometry).

02 · Tokens

Start with a root define

Every mature module begins with a *-root helper that writes CSS custom properties. Callers override those properties later without forking your defines.

my-badge.fscss
@define badge-root(root:root){`
:@use(root) {
  --badge-size: 12px;
  --badge-bg: #8f6bff;
  --badge-fg: #fff;
  --badge-radius: 999px;
  --badge-pad-x: 8px;
  --badge-font: 11px;
}
`}

Prefix every token with your module name (--badge-*, --progress-*, --st-*). That is how five modules share one page without colliding.

03 · Helpers

Define the public surface

Helpers take a selector (and optional knobs), and emit real CSS for that selector. Use @use(param) for parameters.

@define badge(sel:.badge){`
@use(sel) {
  display: inline-flex;
  align-items: center;
  gap: 6px;
  min-height: var(--badge-size);
  padding: 0 var(--badge-pad-x);
  border-radius: var(--badge-radius);
  background: var(--badge-bg);
  color: var(--badge-fg);
  font-size: var(--badge-font);
  font-weight: 600;
  letter-spacing: .04em;
  text-transform: uppercase;
}
`}

@define badge-dot(sel:.badge){`
@use(sel)::before {
  content: '';
  width: 6px;
  height: 6px;
  border-radius: 50%;
  background: currentColor;
  opacity: .85;
 }
`}

/* small theme helpers — optional */
@define badge-theme-success(){
  --badge-bg: #1cac52;
}
@define badge-theme-danger(){
  --badge-bg: #ff5070;
}

Template blocks

When a define must expand loops or multi-line structures, wrap the body in backticks (as circle-progress and st-core do). Keep simple property lists as plain define bodies when you can — easier to read.

04 · Naming

Namespace rules that keep the ecosystem calm

  • Prefix defines with the module id: badge-root, badge, badge-theme-* — not generic root / card.
  • Prefix CSS variables the same way: --badge-bg, never --bg.
  • Prefix keyframes if you ship animations: badge-pulse, not pulse.
  • Accept a selector argument on structural defines so callers map your styles onto their class names.
Good
@badge(.status)
Risky
@card(.card)
Collision
--color: …
05 · Consumption

How others import your module

Selective (preferred in production)

@import((badge-root, badge, badge-theme-success) from my-badge)

@badge-root()
@badge(.status-badge)
.status-ok { @badge-theme-success() }

Wildcard (fine while exploring)

@import((*) from my-badge)

Runtime vs CLI

  • Prototype: https://cdn.jsdelivr.net/npm/fscss@1.2.1/runtime.min.js + a <style> block
  • Ship: fscss my-page.fscss dist/my-page.css and link the CSS only
06 · Metadata

package.json for the module registry

Modules in the ecosystem declare helpers so tooling and docs know the public surface.

package.json
{
  "name": "my-badge",
  "version": "1.0.0",
  "description": "Small status badge module for FSCSS",
  "extension": "fscss",
  "fscss_version": "^1.1.15",
  "file": {
    "usage": {
      "directive": "badge",
      "helpers": [
        "badge-root",
        "badge",
        "badge-dot",
        "badge-theme-success",
        "badge-theme-danger"
      ]
    },
    "modules": ["./my-badge.fscss"],
    "remote": "./my-badge.fscss"
  },
  "keywords": ["fscss", "badge", "ui", "module"],
  "license": "MIT"
}

fscss_version is the minimum language version. If you only need @define, ^1.1.15 is honest. Document 1.2.1 in the README for CDN examples.

07 · End-to-end

Minimal sample page

samples/example.html
<script src="https://cdn.jsdelivr.net/npm/fscss@1.2.1/runtime.min.js" defer></script>
<style>
@import((*) from my-badge)
@badge-root()
@badge(.status-badge)
.ok { @badge-theme-success() }
</style>
<span class="status-badge ok">Live</span>

Ship that HTML in the repo. It’s the fastest way for others to verify the module without reading the whole README.

08 · Watch-outs

Pitfalls

  • Forgetting @use(param) — parameters only expand when referenced with @use(...).
  • Hard-coded selectors inside defines — always take sel (or similar) so the module isn’t tied to one class name.
  • Unprefixed tokens — --size will clash; use --badge-size.
  • Assuming auto-boot — with esm.js you must call reboot() / process yourself; runtime.js auto-scans the page.
  • Loops and selectors — when using @arr / rpt(), isolate with empty{ /* preserve */ } so loop output doesn’t get treated as selectors (see nested-loop docs).
09 · Ship it

Publish checklist

  • *-root define with prefixed CSS variables
  • Public helpers namespaced and listed in package.json
  • Selector parameters on structural defines
  • README: install (runtime + CLI), minimal usage, token table
  • samples/example.html that runs on CDN runtime
  • Honest fscss_version minimum
  • MIT (or clear) license
