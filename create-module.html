Create your first FSCSS module

A module is a small, importable .fscss library: design tokens on a root mixin, namespaced @define blocks, and a README so others can pull only what they need. This page is the checklist — not a replacement for the project tutorial.

00 · Concept

What counts as a module

An FSCSS module is source you import, not a runtime JS package. After compile (CLI or browser runtime), the consumer only ships plain CSS.

  • Solves one job: icons, charts, forms, a page shell, a motion preset…
  • Exposes mixins via @define with a clear prefix (@icon-*, @st-*, @progress-*)
  • Puts shared values on a *-root (or equivalent) so themes override without editing the module
  • Documents selective import so unused mixins never bloat the CSS
01 · Anatomy

Minimum file layout

my-widget.fscss/
├── my-widget.fscss     ← all @define exports
├── README.md              ← install, imports, examples
├── package.json           ← optional metadata for registries
└── samples/
    └── demo.html          ← optional any framework runtime or compiled preview

Small packs can be a single .fscss file in a repo. Larger ones (st-core) add templates and integration folders — start smaller.

02 · Root tokens

One place for theme knobs

Almost every solid module starts with a root mixin that writes CSS variables onto :root (or a scoped selector).

my-widget.fscss
@define widget-root(root:root){`
:@use(root) {
  --widget-bg: #12131a;
  --widget-accent: #8f6bff;
  --widget-radius: 12px;
  --widget-pad: 16px;
}
`}
  • Prefix variables (--widget-*) so packs can share a page
  • Defaults should look good alone; pages override on :root after @widget-root()
  • Optional: accept root so the same tokens can attach to .theme-dark instead of global :root
03 · @define

Namespaced, parameterized mixins

@define widget-card(sel:.widget-card){`
@use(sel) {
  background: var(--widget-bg);
  border-radius: var(--widget-radius);
  padding: var(--widget-pad);
  border: 1px solid color-mix(in srgb, var(--widget-accent) 25%, transparent);
}
`}

@define widget-accent(color){
  --widget-accent: @use(color);
}

Conventions that scale

  • Prefix every public name — widget-card, not generic card
  • Selector parameter — sel:.widget-card so callers can retarget
  • One responsibility per mixin — easier selective imports
  • Prefer tokens over hard-coded colors inside shapes

@import ((widget-card as card) from …) renames only in that file. After as, the original name is unavailable there.

04 · Consumer API

How others pull your module

/* selective — preferred in production */
@import((widget-root, widget-card) from my-widget)

@widget-root()
@widget-card(.pricing-card)

/* or wildcard while exploring */
@import((*) from my-widget)

Document both forms in the README. Show the smallest HTML that proves the mixin works.

<div class="pricing-card">…</div>
05 · Arrays & generation

When the module generates CSS

use some native features. Keep generation bounded (light/medium — not hundreds of rules by default).

  • Document limitations
  • Use empty{ /* preserve */ } when loops must not be parsed as selectors
  • Prefer --vars so JS can update without recompiling the module

Deep dives: arrays, define, st-core EXPLAINED / v2 source.

06 · Test

Prove it in a sample page

  1. Runtime sample: fscss@latest/runtime.min.js + <style> or type="text/fscss"
  2. CLI: test fscss my-widget.fscss /tmp/out.css and open the CSS — no leftover FSCSS syntax
  3. Override tokens on :root and confirm the UI follows
  4. Import only one mixin; confirm the rest did not appear in output

07 · Repo metadata

README and package.json (optional but useful)

README should answer in one screen: what it does, minimum FSCSS version, import snippet, HTML snippet, token list, license.

{
  "name": "my-widget",
  "version": "1.0.0",
  "description": "Short pure-CSS widget pack for FSCSS",
  "extension": "fscss",
  "fscss_version": "^1.2.4",
  "repository": { "type": "git", "url": "https://github.com/you/my-widget.fscss" },
  "keywords": ["fscss", "css", "module"],
  "license": "MIT"
}

Match patterns used by circle-progress / st-core if you want discovery next to other packs.

08 · Publish checklist

Before you call it done

  • □ Prefixed public mixins and CSS variables
  • □ *-root (or documented equivalent) for tokens
  • □ Selective @import ((a, b) from …) example in README
  • □ Minimum FSCSS version stated
  • □ Sample HTML (and optional compiled CSS)
  • □ No reliance on global unscoped tag styles that break host pages
  • □ MIT (or clear license)
