00 · Goal

A real folder, not five demos

By the end you have a small site project: source .fscss, compiled CSS (or runtime while learning), minimal HTML, and a dashboard slice driven by st-core@v2 + icon-mask + circle-progress. Cube is optional eye candy; this tutorial prefers icons and charts you will reuse.

Reference implementation: templates/admin-dashboard · live preview.

01 · Install & run

CLI for shipping, runtime for speed

Option A — Runtime (learn / prototype)

html
<script src="https://cdn.jsdelivr.net/npm/fscss@1.2.4/runtime.min.js" defer></script>
<link type="text/fscss" href="src/site.fscss">

Option B — CLI (production)

bash
npm install -g fscss@1.2.4
fscss src/site.fscss dist/site.css

02 · Project structure

Layout that matches how you ship

my-app/
├── index.html
├── package.json
├── src/
│   ├── site.fscss          ← native tokens + imports
│   └── dashboard.fscss     ← or one file for small sites
├── dist/
│   └── site.css             ← CLI output
└── js/
    └── dashboard.js         ← only --st-pN + UI chrome
  • One file per page — simplest for hubs and landing pages.
  • Split shell / dashboard — when charts and marketing change at different rates.
  • Commit dist/*.css or CI-compile — same idea as the st-core template workflow.
03 · Native FSCSS first

Language features before modules

Modules are optional. A useful page can start with pure FSCSS:

Tokens & shorthand

$accent: #22c55e;
$surface: #12131a;

:root {
  --bg: #0b0c10;
  --accent: $accent!;
}

.card {
  %2(padding, border-radius[: 16px;])
  background: $surface!;
  border: 1px solid rgba(255,255,255,.08);
}

@define, @arr, @event

@define btn(bg:$accent){`
  border: none; padding: 10px 18px; border-radius: 10px;
  background: @use(bg); color: #fff; font-weight: 600;
`}

@arr gaps[8px, 12px, 16px, 24px]

@event theme(mode) {
  if mode: dark { return: #0b0c10; }
  el { return: #f8fafc; }
}

.cta { @btn(#22c55e) }
body { background: @event.theme(dark); }

pattern() (1.2.4)

pattern(0.6: "soft elevated card", `
  background: var(--surface, #181924);
  border-radius: 16px;
  padding: 22px;
  border: 1px solid rgba(255,255,255,.08);
`)

.panel { soft elevated card }

Docs: fscss.devtem.org/docs · pattern() · arrays.

04 · Imports

Select mixins; keep CSS small

@import((*) from st-core@v2)
@import((*) from circle-progress)
@import((*) from icon-mask)
@import((form-root, form-group, form-input, form-label, form-float, form-btn-primary) from form)

Use ((*)) while exploring; switch to named mixins when you know the surface area. Prefixes (@st-*, @progress-*, @icon-*, @form-*) avoid collisions.

06 · icon-mask.fscss

Nav and toolbar icons

@import((*) from icon-mask)
@icon-pack()

:root {
  @icon-color(#94a3b8)
  @icon-size(20px)
}
.nav a.active .icon { @icon-color(#22c55e) }
<a href="#" class="active">
  <span class="icon icon-home"></span> Dashboard
</a>

HTML stays spans + classes; color and size are tokens. Source: icon-mask.fscss.

07 · st-core@v2

Charts without Chart.js

Prefer st-core@v2 (array length → points). Legacy st-core.fscss remains for fixed 8-point demos.

@import((*) from st-core@v2)
@st-root()

@arr data7d[42, 58, 65, 60, 78, 70, 92]
@st-chart-fill(.rev-fill, data7d)
@st-chart-line(.rev-line, data7d)

.chart {
  @st-chart-points(data7d)
  position: relative;
  height: 220px;
}
.rev-fill { --st-accent: #22c55e; opacity: .22; transition: clip-path .7s ease; }
.rev-line { --st-accent: #22c55e; @st-chart-line-width(2.5px) }
<div class="chart" id="revenueChart">
  <div class="rev-fill"></div>
  <div class="rev-line"></div>
</div>

JS only updates values (human → CSS Y):

chart.style.cssText = values
  .map((v, i) => `--st-p${i + 1}: ${100 - v}%;`)
  .join(' ');

09 · Optional form

Withdrawal / settings panel

Add when the page needs inputs — not required for the chart shell.

@import((form-root, form-group, form-input, form-label, form-float, form-btn-primary) from form)
@form-root()
@form-float(.form-group, .form-input, .form-label)

Input before label; placeholder=" " for float-via-:placeholder-shown.

10 · Assemble & ship

One stylesheet story

/* src/dashboard.fscss */
@import((*) from st-core@v2)
@import((*) from circle-progress)
@import((*) from icon-mask)

@st-root()
@progress-root()
@icon-pack()

:root {
  --st-accent: #22c55e;
  @icon-color(#94a3b8)
}

/* + layout rules from the template */
fscss src/dashboard.fscss dist/dashboard.css
# production HTML:
<link rel="stylesheet" href="dist/dashboard.css">
11 · Framework tips

Svelte · React · Next

  • Compile FSCSS in CI or a prebuild script — ship .css, not the runtime, in production bundles.
  • Data → CSS variables — frameworks own state; set style={`--st-p1: ${100-v}%`} or element.style.setProperty. Same contract as the template’s dashboard.js.
  • Svelte — see integration/svelte in st-core: component binds series → --st-pN; styles from compiled CSS.
  • React / Next — import the compiled CSS once (layout or global); chart components only patch variables. Avoid running the FSCSS runtime per component mount.
  • SSR — link compiled CSS in the document head; no browser compile on first paint.
  • Design tokens — map theme providers to the same --st-* / --progress-* names the modules already read.

FSCSS does not replace your framework.
