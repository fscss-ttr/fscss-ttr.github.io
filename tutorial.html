Building a full site with FSCSS modules

One project, five modules, every import explained. This walks through building a real multi-section site — marketing page, dashboard, and a settings panel — by combining customizable, st-core, circle-progress (ring · pie · steps), form, and cube. Each step covers exactly what you import, what it builds in the DOM, what it's good for, and what version of FSCSS it needs.

00 · What you're building

A creator dashboard, not five isolated demos

The example running through this tutorial is a small internal tool for DevTemple-style creators: a page that shows earnings over time, tracks progress toward a payout threshold, lets a creator request a withdrawal, and shows a small 3D badge when they hit a milestone. It's deliberately ordinary — the point isn't the dashboard, it's that five separately-maintained CSS modules sit on one page without fighting each other.

Every module in this ecosystem follows the same rule: it reads design tokens from its own @*-root mixin, renders its shapes with plain CSS (clip-path, gradients, transforms, pseudo-elements), and — where JavaScript shows up at all — only ever writes a CSS custom property. That rule is what makes combining them straightforward instead of a specificity fight.

Every code block below is copy-paste real — pulled from each module's actual mixin names and import syntax. The screenshots are reference images from each module's own write-up.

01 · Setup

Two ways to bring FSCSS in

Pick one depending on where you are in the build. Both compile the same shorthand to the same output — the only difference is when compilation happens.

Option A — CDN runtime (fastest to start)

Good for prototyping, demos, and this tutorial. The runtime script compiles any @fscss-flavored <style> block in the browser as the page loads.

html
<script src="https://cdn.jsdelivr.net/npm/fscss@1.2.1/runtime.min.js" defer></script>

Option B — CLI, compiled ahead of time (production)

No runtime request, no in-browser compile step. This is what you switch to once the site is ready to ship.

bash
# once, globally
npm install -g fscss

# compile a source file to plain CSS
fscss site.fscss dist/site.css
Runtime weight
~10kb (CDN mode)
Compiled weight
~0.5kb / module
Minimum FSCSS
v1.2.1+
02 · Project structure

How a real FSCSS site is laid out

There's no bundler and no framework, so the structure stays close to the output. One source .fscss file per page (or one shared file plus page-specific ones), compiled into a matching .css file that ships to the browser.

creator-studio/
├── index.html                ← marketing / landing page
├── dashboard.html             ← the combined build in this tutorial
├── package.json
├── src/
│   ├── shell.fscss            ← customizable: nav, container, tokens
│   ├── dashboard.fscss        ← st-core + circle-progress + form + cube
│   └── tokens.fscss           ← shared $variables, brand overrides
├── dist/
│   ├── shell.css              ← compiled output, committed or built in CI
│   └── dashboard.css
└── assets/
    └── images/

Two working patterns, both fine:

  • Split by concern (shown above) — one .fscss file per structural layer, each compiled to its own .css. Easiest to reason about when different modules change at different rates.
  • One file per page — a single page.fscss that imports everything that page needs and compiles to one page.css. Simplest for smaller sites like this hub.
03 · The import system

What @import actually does here

FSCSS imports are selection-based, not file-based — you name which mixins you want out of a module, and only those get compiled into your output. This is the mechanism that keeps the ~0.5kb-per-module compiled weight honest: an unused mixin never ships.

Selective import — name exactly what you use

@import((page-hero, page-btn, page-btn-primary) from customizable)

Only page-hero, page-btn, and page-btn-primary compile. The module's footer, 404, and feature-grid mixins never enter your CSS, even though they live in the same source file.

Wildcard import — pull in everything

@import((*) from st-core)

Use this while you're still deciding which pieces of a module you need — during the first pass of a build, or for a module like st-core where a dashboard typically ends up using most of it anyway.

Multiple imports, one file

@import((*) from st-core)
@import((*) from circle-progress)
@import((form-root, form-group, form-float) from form)

Imports stack. Order rarely matters between different modules since each one's mixins are namespaced to its own prefix (@st-*, @form-*, @page-*, @cube-*, @progress-*) — no collisions between modules that were built independently.

Rule of thumb used throughout this tutorial: wildcard-import a module the first time you reach for it, then go back and narrow to a selective import once the page is stable and you know exactly which mixins survived.

Step 1 of 5 — customizable.fscss

Lay down the page shell

Every other module in this build inherits spacing, radius, and color from whatever page-root writes to :root. Setting the shell first means the dashboard, the form, and the badge all line up without individually tuned margins.

What it imports

dashboard.fscss
@import((page-root, page-base, page-hero,
         page-btn, page-btn-primary) from customizable)

@page-root()
@page-base(body)

What that sets up

  • page-root — design tokens on :root (accent, radius, spacing, surfaces).
  • page-base — body typography and background.
  • Optional later: page-hero, page-btn for marketing blocks on the same token layer.

What it's good for

Recurring page chrome — nav, hero, footer, long-form type — so dashboard widgets don't invent their own spacing system.

FSCSS v1.2.1+

Step 2 of 5 — st-core.fscss

Dashboard charts and stat cards

st-core is the foundational charting module: area fills via clip-path: polygon(), line strokes, dots, grids, and stat cards — all driven by CSS custom properties. No charting JS.

What it imports

dashboard.fscss
@import((*) from st-core)

@st-root()
@st-stat-card(.stat-card)
@st-chart-fill(.chart-fill)
@st-chart-line(.chart-line)
@st-chart-dots(.chart-dot-, 7px)
@st-chart-grid(.chart-grid, 8, 7)

/* optional: feed points from an array (see nested-loop / st-chart-n patterns) */
@arr st-values[68, 59, 70, 35, 58, 22, 42, 55]

What it's good for

Earnings over time, category bars, KPI cards. Point data lives in CSS variables (or an @arr + define that writes --st-p1…N). Updating a variable updates the shape.

Requires
FSCSS v1.2.1+
Technique
clip-path + vars

Step 3 of 5 — circle-progress.fscss

Payout goal ring (and friends)

circle-progress.fscss started as a single conic-gradient ring. The current module also covers solid pies, multi-slice pies, and step rings — same token layer, different defines.

What it imports

dashboard.fscss
@import((*) from circle-progress)

@progress-root()
@circle-progress(.progress-circle)

.p72 { @progress-range(72) }
.p41 {
  @progress-range(41)
  --progress-color-arc: #4d9fff;
  --progress-color-glow: rgba(77,159,255,.45);
}

/* optional shapes on the same page */
@circle-pie(.circle-pie)
@circle-steps(.circle-steps)
.steps-5 { @steps-done(5) @steps-total(8) }

Markup

<div class="progress-circle p72">72%</div>
<div class="circle-steps steps-5">5/8</div>

What it's good for

Single-value goals (payout threshold, completion %), step wizards, and small pie breakdowns. Nest rings by nesting elements and overriding --progress-size / --progress-stroke.

Requires
FSCSS v1.1.15+ · demos 1.2.1
Technique
conic-gradient + mask

Step 4 of 5 — form.fscss

Withdrawal form with floating labels

Visual states (rest, focus, filled, success) come from CSS — especially :placeholder-shown — not from toggling classes on every keystroke.

What it imports

dashboard.fscss
@import((form-root, form-group, form-input, form-label,
         form-float, form-help, form-btn, form-btn-primary) from form)

@form-root()
@form-group(.form-group)
@form-input(.form-input)
@form-label(.form-label)
@form-float(.form-group, .form-input, .form-label)
@form-help(.form-help)
@form-btn(.form-btn)
@form-btn-primary(.form-btn-primary)

Markup — input before label

<div class="form-group is-success">
  <input class="form-input" type="number" placeholder=" ">
  <label class="form-label">Withdrawal amount</label>
  <span class="form-help">Available: $2,140</span>
</div>
<button class="form-btn form-btn-primary">Request withdrawal</button>
  • Placeholder must be a literal space (placeholder=" ") so :placeholder-shown works.
  • Input must precede the label — the float rule uses the adjacent sibling selector.
Requires
FSCSS v1.2.1+

0 for visual states

Step 5 of 5 — cube.fscss

Milestone badge

A small real-3D cube (preserve-3d + six faces) as a milestone flourish — easy to cut if the page is heavy; nothing else depends on it.

What it imports

dashboard.fscss
@import((cube-root, cube-wrapper, cube-face, cube-face-front,
         cube-micro-glass) from cube)

@cube-root()
@cube-wrapper(.milestone-badge)
@cube-face(.milestone-badge div)
@cube-face-front(.milestone-badge .f1)
@cube-micro-glass(.milestone-badge .f1)

.milestone-badge {
  @cube-size(48px)
  transform: rotateY(30deg) rotateX(15deg);
  animation: badge-spin 6s linear infinite;
}

@keyframes badge-spin {
  to { transform: rotateX(375deg) rotateY(390deg); }
}

Putting it together

Full assembled dashboard.fscss

Every import from the five steps, one file. Use the CDN runtime while building; compile with the CLI for production.

src/dashboard.fscss
/* shell */
@import((page-root, page-base) from customizable)
@page-root()
@page-base(body)

/* charts + stats */
@import((*) from st-core)
@st-root()
@st-stat-card(.stat-card)
@st-chart-fill(.chart-fill)
@st-chart-line(.chart-line)
@st-chart-dots(.chart-dot-, 7px)

/* payout goal ring */
@import((*) from circle-progress)
@progress-root()
@circle-progress(.progress-circle)

/* withdrawal form */
@import((form-root, form-group, form-input, form-label,
         form-float, form-help, form-btn, form-btn-primary) from form)
@form-root()
@form-group(.form-group)
@form-input(.form-input)
@form-label(.form-label)
@form-float(.form-group, .form-input, .form-label)
@form-btn(.form-btn)
@form-btn-primary(.form-btn-primary)

/* milestone badge */
@import((cube-root, cube-wrapper, cube-face-front, cube-micro-glass) from cube)
@cube-root()
@cube-wrapper(.milestone-badge)
@cube-face-front(.milestone-badge .f1)
@cube-micro-glass(.milestone-badge .f1)

/* brand override — cascades across modules */
:root {
  --page-accent: #8f6bff;
  --st-accent: #8f6bff;
  --progress-color-arc: #8f6bff;
}
Going to production

Compile once, ship plain CSS

bash
fscss src/dashboard.fscss dist/dashboard.css
<!-- while building -->
<script src="https://cdn.jsdelivr.net/npm/fscss@1.2.1/runtime.min.js" defer></script>

<!-- production -->
<link rel="stylesheet" href="dist/dashboard.css">
